1 ВВЕДЕНИЕ
1.1 Наименование программы: «Библиотека и редактор файлов KiCad на 
языке Python», рабочее название kicadfp (далее по тексту Программа).
1.2  Краткая  характеристика  области  применения.  Программа  
предназначена для автоматизированной работы с файлами САПР печатных  
плат KiCad вне самой САПР: чтение файлов, изменение их содержимого из  
скриптов и из интерфейса пользователя, сохранение результата в формате,  
который без ошибок открывается в KiCad. Область применения: учебное и  
инженерное  проектирование  печатных  плат,  подготовка  и  массовое  
исправление библиотек компонентов, генерация корпусов по параметрам,  
автоматизация рутинных операций при ведении библиотек кафедры и личных 
библиотек разработчика.
1.3 На первом этапе разработки Программа поддерживает один тип  
сущностей KiCad: посадочные места компонентов (footprints), хранящиеся в  
файлах с расширением .kicad_mod, и библиотеки посадочных мест в виде  
каталогов с расширением .pretty. Последующие этапы расширяют Программу 
на схемы (.kicad_sch), платы (.kicad_pcb), библиотеки символов (.kicad_sym),  
правила проектирования (.kicad_dru), таблицы библиотек (fp-lib-table, sym-lib-
table) и файлы проекта (.kicad_pro). Требования к последующим этапам  
приведены в разделе 7 в объеме, достаточном для того, чтобы архитектура  
первого этапа их не исключала.

4 ТРЕБОВАНИЯ К ПРОГРАММЕ
4.1 Требования к функциональным характеристикам
4.1.1  Поддерживаемые  форматы.  Программа  должна  читать  и  
записывать файлы посадочных мест в формате S-выражений KiCad версий 6,  
7, 8 и 9 (токен footprint, версия формата в поле version). Файлы старого  
формата PCBnew-LibModule-V1 (библиотеки .mod KiCad версий 4 и ниже) на 
первом этапе поддерживаются только на чтение с преобразованием в  
современный формат; запись в старый формат в первый этап не входит.  
Библиотека  .pretty  представляет  собой  каталог,  в  котором  каждый  
файл .kicad_mod является одним корпусом; Программа должна уметь  
открывать каталог как библиотеку, перечислять корпуса, добавлять, удалять,  
переименовывать и копировать корпуса между библиотеками.
4.1.2 Модель данных корпуса. В памяти корпус представляется  
объектом Footprint со следующими сущностями (полный перечень полей  
приведен в приложении Б):
1) свойства корпуса: имя, версия формата, генератор, слой (F.Cu или  
B.Cu), описание (descr), ключевые слова (tags), атрибуты (attr: smd,  
through_hole, board_only, exclude_from_pos_files, exclude_from_bom), 
поля свойств (property), зазоры и параметры маски и пасты (clearance, 
solder_mask_margin, solder_paste_margin, solder_paste_ratio), тип зоны 
3
=== PAGE 4 ===
подключения (zone_connect), точка привязки (anchor), уникальные  
идентификаторы (tstamp или uuid);
2) текстовые  поля:  обозначение  (Reference),  значение  (Value),  
пользовательские тексты (fp_text user, в новых версиях fp_text и  
property) с параметрами положение, поворот, слой, размер шрифта,  
толщина, выравнивание, зеркальность, видимость;
3) графические элементы: линия (fp_line), прямоугольник (fp_rect),  
окружность (fp_circle), дуга (fp_arc), полигон (fp_poly), кривая Безье 
(fp_curve) с параметрами координаты, слой, ширина линии или  
параметры stroke, заливка;
4) контактные площадки (pad): номер, тип (thru_hole, smd, connect,  
np_thru_hole), форма (circle, rect, oval, trapezoid, roundrect, custom),  
координаты и поворот, размер, отверстие (drill: диаметр, овальное  
отверстие, смещение), слои, параметры формы (roundrect_rratio,  
chamfer_ratio, chamfer), зазоры и параметры маски и пасты на уровне 
площадки, зона подключения, номер и имя цепи (net), имя вывода  
(pinfunction), тип вывода (pintype), для формы custom описание  
примитивов и опций;
5) трехмерные модели (model): путь к файлу, смещение, масштаб,  
поворот, флаг скрытия;
6) зоны и группы внутри корпуса (zone, group) на первом этапе не  
редактируются, но должны сохраняться без изменений.
4.1.3  Операции  редактирования.  Программа  должна  позволять  
пользователю выполнять следующие действия над открытым корпусом:  
изменять любое свойство корпуса из перечня п. 4.1.2; добавлять, удалять и  
изменять текстовые поля; добавлять, удалять и изменять графические  
элементы, в том числе перемещать, поворачивать, зеркально отражать и  
менять слой; добавлять, удалять и изменять площадки, в том числе изменять  
номер, тип, форму, размер, координаты, поворот, отверстие и набор слоев;  
выполнять групповые операции над набором площадок (перенумерация по  
правилу, сдвиг, поворот вокруг точки, смена слоев, задание общего размера);  
генерировать типовые корпуса по параметрам (двухрядные DIP с заданным  
числом выводов, шагом и расстоянием между рядами, однорядные и  
двухрядные штыревые разъемы, выводные резисторы и конденсаторы с  
заданным межцентровым расстоянием, диоды, транзисторы с выводами в  
линию) с автоматическим построением контура шелкографии и области  
размещения (F.Fab, F.CrtYd).
4.1.4 Сохранение без потерь (round-trip). Ключевое требование этапа.  
Программа не должна повреждать структуру файла и не должна удалять  
данные, которые не поддерживаются напрямую. Для этого файл разбирается в 
4
=== PAGE 5 ===
дерево S-выражений целиком; типизированные объекты модели (площадки,  
графика, тексты) являются представлениями над узлами этого дерева; узлы  
неизвестного типа, неизвестные атрибуты известных узлов и порядок узлов  
сохраняются как есть. При сохранении файла, который открыт и не изменен,  
результат должен совпадать с исходным по содержанию S-выражений  
(сравнение по разобранному дереву; допускается различие в пробелах,  
переводах строк и формате записи чисел). При изменении одного элемента  
изменяться в файле должен только этот элемент. Числа записываются в  
формате KiCad: без лишних нулей, с точностью не хуже 0,000001 мм; строки  
экранируются по правилам KiCad; порядок токенов внутри узла соответствует 
порядку, который использует KiCad при записи, чтобы файл читался в KiCad и 
корректно отображался в системах контроля версий.
4.1.5 Проверка корректности. Перед сохранением и по отдельной  
команде Программа выполняет проверку корпуса и выводит список замечаний 
с уровнями «ошибка» и «предупреждение»: дублирующиеся номера площадок 
(с учетом того, что в KiCad одинаковые номера допустимы и означают один  
вывод, это предупреждение); площадка без слоев; сквозная площадка без  
отверстия и SMD-площадка с отверстием; отверстие больше площадки;  
отсутствие обязательных полей Reference и Value; текст Reference или Value не 
на слое шелкографии или F.Fab; графика на несуществующем слое;  
недопустимые значения перечислений (тип, форма, слой); нулевые или  
отрицательные  размеры;  отсутствие  области  размещения  (CrtYd)  как 
предупреждение. Ошибки блокируют сохранение только по явному указанию 
пользователя (режим строгой проверки), по умолчанию выводятся как список.
4.1.6 Программный интерфейс (API). Программа оформляется как пакет 
Python kicadfp с публичным интерфейсом, достаточным для использования без 
графического интерфейса. Минимальный состав: функции load(path) и  
loads(text) для чтения, save(footprint, path) и dumps(footprint) для записи, класс 
Footprint с коллекциями pads, graphics, texts, models и методами доступа к  
свойствам; классы Pad, Line, Rect, Circle, Arc, Poly, Text, Model с атрибутами, 
соответствующими  токенам  формата;  класс  Library  для  работы  с  
каталогом .pretty (list, get, add, remove, rename, copy_to); модуль generators с  
функциями построения типовых корпусов; функция validate(footprint) с  
возвратом списка замечаний. Все координаты и размеры в API задаются в  
миллиметрах, углы в градусах. Пример использования API приведен в  
приложении В.
4.1.7 Интерфейс командной строки. Утилита kicadfp предоставляет  
команды: info (вывод сводки по корпусу: имя, слой, число площадок, список  
слоев, габариты), list (перечень корпусов библиотеки), validate, set (изменение 
свойства по пути вида pad[3].size или footprint.descr), pads (табличный вывод

площадок), gen (генерация типового корпуса с параметрами), fmt (перезапись 
файла в каноническом форматировании KiCad без изменения содержания),  
convert (преобразование старого формата .mod в .pretty). Все команды

4.1.8 Графический интерфейс пользователя. Графический интерфейс  
реализуется на PySide6 (Qt) и содержит: дерево библиотек и корпусов; панель 
свойств корпуса; таблицу площадок с редактированием ячеек (номер, тип,  
форма, X, Y, поворот, размер X, размер Y, отверстие, слои); таблицу  
графических элементов и текстов; графическое поле предварительного  
просмотра  корпуса  с  отображением  слоев  в  цветах  KiCad,  сеткой, 
масштабированием  и  выбором  элемента  щелчком;  команды  открыть, 
сохранить, сохранить как, отменить и повторить, проверить, создать типовой  
корпус. Изменения в таблицах и на поле просмотра применяются к одной и той 
же модели данных. Графический интерфейс является обязательным для  
первого этапа, но реализуется после API и командной строки и может быть  
сдан отдельной версией.
4.1.9 Входные и выходные данные. Входные данные: файлы .kicad_mod, 
каталоги .pretty, файлы старого формата .mod (только чтение), параметры  
генераторов из командной строки или файла параметров в формате JSON.  
Выходные данные: файлы .kicad_mod и каталоги .pretty, отчеты проверки в  
текстовом виде и в JSON, изображения предварительного просмотра в  
форматах SVG и PNG. Кодировка всех текстовых файлов UTF-8, перевод  
строки LF, что соответствует записи самой САПР KiCad.
4.2 Требования к надежности
4.2.1 Программа не должна терять или искажать данные пользователя.  
Запись файла выполняется через временный файл в том же каталоге с  
последующим переименованием, чтобы при сбое исходный файл оставался  
целым. При открытии файла с синтаксической ошибкой Программа сообщает 
номер строки и позицию ошибки и не создает частично разобранную модель.  
При обнаружении неизвестных узлов Программа продолжает работу и  
сохраняет их без изменений.
4.2.2 Все изменения, доступные из графического интерфейса, обратимы 
(отмена  и  повтор  не  менее  чем  на  100  шагов).  Перед  закрытием 
несохраненного корпуса выводится запрос подтверждения.
4.2.3 Программа сопровождается набором автоматических тестов:  
модульные тесты разбора и записи для каждого типа узла, тесты round-trip на  
наборе не менее 200 корпусов из стандартных библиотек KiCad (каталоги  
Package_DIP.pretty,  Resistor_THT.pretty,  Capacitor_THT.pretty,  
Connector_PinHeader_2.54mm.pretty,  Package_SO.pretty  и  других),  тесты

4.3 Условия эксплуатации
4.3.1  Программа  эксплуатируется  на  персональном  компьютере  
пользователя в обычных условиях помещения. Специальных требований к  
квалификации обслуживающего персонала нет; пользователю достаточно  
навыков работы с KiCad и с командной строкой операционной системы. Для  
использования API требуется знание Python на уровне написания скриптов.
4.4 Требования к составу и параметрам технических средств
4.4.1 Минимальная конфигурация: процессор с архитектурой x86-64 или 
ARM64, оперативная память 2 ГБ, свободное место на диске 200 МБ (с учетом 
Python и Qt), монитор с разрешением не ниже 1280 на 720 точек для  
графического интерфейса. Программа не требует сетевого подключения.
4.5 Требования к информационной и программной совместимости
4.5.1 Язык реализации Python версии 3.10 и выше. Ядро (разбор, модель, 
запись, проверка, генераторы) не должно зависеть от сторонних пакетов,  
кроме стандартной библиотеки Python, чтобы его можно было использовать в 
скриптах и в среде KiCad (встроенный Python). Графический интерфейс  
использует PySide6, экспорт изображений использует стандартные средства  
Qt или пакет cairosvg; эти зависимости объявляются как необязательные  
(extras) при установке.
4.5.2 Операционные системы: Windows 10 и 11, Linux (дистрибутивы с  
glibc 2.31 и новее), macOS 12 и новее. Программа распространяется как пакет 
для установки через pip (wheel и sdist) и как исходный код в репозитории Git с 
файлами pyproject.toml, README и лицензией.
4.5.3 Совместимость с KiCad. Файлы, записанные Программой, должны 
без ошибок и предупреждений открываться в редакторе посадочных мест  
KiCad 8 и 9 и корректно отображаться. Файлы, записанные KiCad 6 и 7,  
должны читаться Программой. Форматы файлов приняты по официальному  
описанию KiCad (документация «S-Expression Formats», раздел Footprint) и по 
фактическому поведению KiCad, проверяемому на файлах стандартных  
библиотек. Перечень поддерживаемых токенов приведен в приложении А.
4.5.4 Программа не должна использовать внутренний Python API самой 
KiCad (модуль pcbnew), чтобы работать без установленной САПР. Для  
проверки совместимости в составе тестов допускается необязательный тест,
