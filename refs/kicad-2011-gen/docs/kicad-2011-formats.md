## 2. Библиотека компонентов `.lib`

### 2.1 Чтение строк (`GetLine`, `common/string.cpp:157-169`)

- Строки, начинающиеся с `#`, пустые и начинающиеся с `\r`/`\n`, **пропускаются везде** (в том числе внутри `DRAW` и `$FPLIST`).
- Хвост `\r\n` обрезается. Буфер строки — 8000 байт (`general.h:27`); более длинная строка режется `fgets` и ломает разбор.
- Строка из одних пробелов **не** пропускается: внутри `DEF` это `strtok` → `NULL` → `strcmp(NULL, ...)` — краш KiCad.

### 2.2 Файл целиком

```
EESchema-LIBRARY Version 2.3  Date: <дата>        ← class_library.cpp:795-796 (два пробела перед Date)
#encoding utf-8                                    ← :799 (комментарий, парсером игнорируется)
#
# <имя компонента>                                 ← class_libentry.cpp:542 (косметика)
#
DEF ...
...
ENDDEF
#
#End Library                                       ← class_library.cpp:718
```

Проверка заголовка (`class_library.cpp:430-492`): первый токен (без регистра) начинается с `EESCHEMA-LIB`; второй токен **ровно** `Version` (с регистром); третий `major.minor`, `major ≥ 1`, `0 ≤ minor ≤ 99`. Неверная версия не фатальна, но оставляет `versionMajor/Minor` неинициализированными → всегда писать `2.3`.

Главный цикл (`:494-537`): реагирует только на `$HEADER` (устаревший блок до `$ENDHEADER`; без него — вся библиотека не грузится) и на строки, начинающиеся с `DEF` (без регистра). Всё остальное на верхнем уровне молча игнорируется. Компонент с ошибкой разбора отбрасывается с `wxLogWarning`, библиотека грузится дальше. Дубликаты имён — только warning. Версии ≤ 2.3 читают отдельный `.dcm` (`class_library.h:37-38`).

Компоненты записываются в порядке `map` (сортировка имён **без учёта регистра**, `class_libentry.h:24-33`).

### 2.3 Строка `DEF` (`class_libentry.cpp:573-578` запись, `:690-766` чтение)

```
DEF <name> <ref> 0 <pinNameOffset> <Y|N> <Y|N> <unitCount> [<L|F>] [<P|N>]
```

| № | Токен | Смысл |
|---|---|---|
| 1 | `name` | имя (= текст поля Value). Префикс `~` ⇒ Value невидимо. **При загрузке приводится к верхнему регистру** (`strupper`, `:736`); `F1` потом восстанавливает регистр текста, но ключ в карте остаётся верхним |
| 2 | `ref` | префикс ссылки (`DD`, `R`, `#PWR`). Ровно `~` ⇒ пустой и невидимый |
| 3 | `0` | неиспользуемое «число выводов», должно быть целым |
| 4 | `pinNameOffset` | отступ имени вывода внутрь корпуса, мил; `0` = имена снаружи (над выводом). По умолчанию 40 |
| 5 | показывать номера | `N` ⇒ нет, любой другой символ ⇒ да |
| 6 | показывать имена | так же |
| 7 | `unitCount` | секций в корпусе; `< 1` ⇒ 1 |
| 8 | `L`/`F` | опционально; `L` = секции не взаимозаменяемы |
| 9 | `P`/`N` | опционально; `P` = символ питания (`ENTRY_POWER`) |

Ошибка в токенах 1–7 → «Wrong DEF format», перемотка до `ENDDEF`, компонент пропущен.

### 2.4 Строки внутри `DEF` (`class_libentry.cpp:769-802`, порядок проверок)

1. `Ti …` (по первым двум символам) → `LoadDateAndTime` — **всегда возвращает false** из-за бага (`sscanf` по буферу, уже обрезанному `strtok` до `"Ti"`, `:1175-1179`) → компонент отбрасывается. **Никогда не писать `Ti`.**
2. Первый символ `F` → поле (§2.5).
3. Первый токен ровно `ENDDEF` → конец.
4. Первый токен ровно `DRAW` → графика (§2.6).
5. Первый токен начинается с `ALIAS` (5 символов) → остаток строки разбивается по пробелам/табам; регистр сохраняется.
6. Первый токен начинается с `$FPLI` → строки до `$ENDFPLIST` (вся строка, без регистра); у каждой строки отбрасывается **первый символ** (писатель ставит пробел: `class_libentry.cpp:642`).
7. Всё остальное игнорируется. `ENDDEF` в конце файла может отсутствовать.

Порядок записи (`:536-677`): `DEF`, `F0…F3` (только непустые), пользовательские поля с перенумерацией от 4, `ALIAS`, `$FPLIST`, `DRAW…ENDDRAW`, `ENDDEF`.

### 2.5 Поля `F<n>` (`lib_field.cpp:116-141` запись, `:147-268` чтение)

```
F<id> "<text>" <x> <y> <size> <H|V> <V|I> <L|C|R> <T|C|B><I|N><B|N> ["<имя поля>"]
```

- `id`: 0 Reference, 1 Value, 2 Footprint, 3 Datasheet, ≥ 4 пользовательские (`template_fieldnames.h:21-31`). Имя пишется только для `id ≥ 4` и только если отличается от `Field<n>`; при чтении для `id ≥ 4` имя ищется как следующая строка в кавычках (нет → пустое имя).
- `F<id>` без пробела; текст **обязательно в кавычках** (иначе компонент отброшен). После закрывающей кавычки должно быть хоть что-то.
- `size` — один размер (x = y). `H`/`V` — ориентация; `V`/`I` — видим/невидим; иное → ошибка.
- После текста допустимо **ровно 5** токенов (`x y size H V`; выравнивание = центр) или **≥ 7** (`x y size H V C CNN`). **6 токенов — фатально** (триплет vjust пустой, `:218-246`).
- Триплет: `[TCB]` vjust, `I` = italic, `B` = bold (иначе `N`).
- Пустой текст пишется как `"~"`; но `LIB_COMPONENT::Save` пустые поля вообще не пишет.

### 2.6 Графика `DRAW … ENDDRAW` (`class_libentry.cpp:811-890`)

Диспетчер по **первому байту** строки: `A C T S X P B`; иное (в т.ч. `F`) → «undefined DRAW command», компонент отброшен. `ENDDRAW` — по первым 7 символам. Все разборы идут с `&line[2]`.

Общие колонки: `unit` (0 = общий для всех секций, иначе 1..N), `convert` (0 = общий, 1 = обычный, 2 = DeMorgan), `width` (0 = толщина по умолчанию, `g_DrawDefaultLineThickness` = 6), `fill` ∈ `N` (нет), `F` (цветом контура), `f` (фоном) — `lib_draw_item.cpp:14`.

| Тип | Формат записи | Минимум токенов | Файл |
|---|---|---|---|
| Дуга | `A cx cy r t1 t2 unit convert width fill x1 y1 x2 y2` | 8 (концы только при 13) | `lib_arc.cpp:88-157` |
| Окружность | `C cx cy r unit convert width fill` | 6 | `lib_circle.cpp:41-70` |
| Прямоугольник | `S x1 y1 x2 y2 unit convert width fill` | 7 | `lib_rectangle.cpp:43-73` |
| Полилиния | `P n unit convert width  x1 y1  x2 y2 … fill` | 4 + 2n | `lib_polyline.cpp:40-113` |
| Безье | `B n unit convert width  x1 y1 … fill` | ровно 4 + 2n | `lib_bezier.cpp:40-113` |
| Текст | `T orient x y size attr unit convert <text>  <Italic|Normal> <bold> <hj> <vj>` | 8 | `lib_text.cpp:38-161` |
| Вывод | `X name num x y len orient numSize nameSize unit convert etype [attrs]` | 11 | `lib_pin.cpp:541-773` |

Детали:

- **Дуга**: углы в десятых градуса. При записи `t > 1800` переводится в `t − 3600`; при чтении нормализуется в `[0, 3600)`. Если токенов < 13, концы вычисляются как `centre + R·(cos t, sin t)`.
- **`A`/`C`/`S`**: буфер `tmp` для `fill` не инициализируется и `m_Fill` не сбрасывается → при пропуске токена читается мусор. **Всегда писать fill.**
- **Полилиния**: `n ≤ 0` — ошибка; недостающие точки — ошибка. Два пробела перед каждой парой — так пишет KiCad (`:49`).
- **Безье**: заголовок ровно 4 токена (`!= 4`); недостающие точки → `sscanf(NULL)` → **краш**.
- **Текст**: `orient` 0 или 900; `attr` бит 0 = невидим. Сначала пробуется форма в кавычках (`"%[^"]"`, `''` → `"`), иначе `%s` с заменой `~` → пробел. Между текстом и `Italic|Normal` KiCad пишет два пробела. `bold` — число > 0. `hj`/`vj` — `L C R` / `T C B`, невалидные молча игнорируются.
- **Вывод**: `(x, y)` — **точка подключения** (там рисуется кружок, `lib_pin.cpp:1034-1054`; координата для netlist — `sch_component.cpp:1563-1569`). Буква ориентации задаёт направление линии **от точки подключения к корпусу**: `R` → +X, `L` → −X, `U` → +Y, `D` → −Y. Следовательно вывод на левой стороне корпуса имеет ориентацию `R`, на правой `L`, сверху `D`, снизу `U`.
  - `name`: `~` = нет имени; `~фрагмент~` внутри имени рисуется с надчёркиванием; пробелы невозможны (`SetName` заменяет на `_`).
  - `num`: **не более 4 байт** — хранится в `long` (`strncpy(&m_number, …, 4)`, `:674`); лишнее молча отрезается.
  - `etype`: `I` input, `O` output, `B` bidi, `T` tristate, `P` passive, `U` unspecified, `W` **power in**, `w` **power out** (регистр!), `C` open collector, `E` open emitter, `N` not connected. Иное → компонент отброшен.
  - `attrs` (12-й токен, без пробелов, порядок записи `N I C L V F X`): `N` невидимый вывод (`PINNOTDRAW`), `I` инверсия, `C` clock, `L` active-low input, `V` active-low output, `F` falling-edge clock, `X` non-logic; `~` игнорируется; иное → компонент отброшен.
  - Значения по умолчанию: длина 300, размеры текста 50/50, тип Unspecified в конструкторе (Input — в диалоге).

Сортировка при записи (`lib_draw_item.cpp:90-108` + `DoCompare`): по `convert`, затем `unit`, затем тип в порядке `A C T S P B X`, затем для выводов — упакованный в `long` номер (little-endian!), имя без регистра, x, y; для остальных — координаты. Для загрузки порядок не важен.

### 2.7 Символ питания

Компонент с флагом `P` в `DEF`, ссылкой `#PWR`, одним **невидимым** выводом типа `W` (Power In), имя вывода = имя цепи. Невидимый `W`-вывод создаёт неявную глобальную метку (`netlist.cpp:666-679`); `w` (Power Out) этого не делает. При аннотации KiCad сам добавляет `#` к ссылке символа питания (`sch_sheet_path.cpp:238-249`).

### 2.8 Экспорт одного символа `.sym` (`symbedit.cpp:150-200`)

Тот же синтаксис; заголовок `EESchema-LIBRARY Version 2.3  SYMBOL  Date: …`, без `#encoding`, поля `F0`, `F1`, хвост `DEF` всегда `1 0 N`; при загрузке заголовок не проверяется.

## 3. Документация `.dcm`

Файл с тем же именем, что `.lib`, рядом (`class_library.cpp:592, 737`). Пишется только редактором библиотек («Сохранить библиотеку», `libedit.cpp:279`); кеш-библиотека `.dcm` не имеет. Результат чтения игнорируется — сломанный `.dcm` не мешает загрузке `.lib`.

```
EESchema-DOCLIB  Version 2.0  Date: <дата>       ← class_library.cpp:766 (два пробела перед Version и перед Date)
#
$CMP <имя>                                        ← имя с байта 5 до конца строки (может содержать пробелы)
D <описание>                                      ← значения с байта 2
K <ключевые слова>
F <файл документации / URL>
$ENDCMP
#
#End Doc Library
```

Чтение (`class_library.cpp:583-663`): первые 10 символов заголовка без регистра = `EESchema-D`; каждая строка верхнего уровня обязана начинаться с `$CMP`, иначе «$CMP command expected» и стоп; имя сопоставляется с компонентом/алиасом без регистра; неизвестное имя — блок молча пропускается; неизвестная буква внутри блока игнорируется; `$ENDCMP` по 7 символам. Записываются только записи, где есть хоть одно из D/K/F, в порядке имён без регистра.

## 4. Проектный файл `.pro`

`wxFileConfig` (INI): `[секция]`, вложенные `[a/b]`, `ключ=значение` без пробелов. Ключи до первой секции — корневые. Эталон — `testing_data/346_8.pro`:

```
update=Ср 02.09.26 19:42:16
version=1
last_client=kicad
[cvpcb]
version=1
NetITyp=0 … NetType=0
[cvpcb/libraries]
EquName1=devcms
[pcbnew]
version=1
PadDrlX=320 … ShowMRa=1
[pcbnew/libraries]
LibDir=
LibName1=sockets … LibName10=dip_sockets
[eeschema]
version=1
LibDir=
NetFmt=1
HPGLSpd=20
HPGLDm=15
HPGLNum=1
offX_A4=0 … offY_E=0
RptD_X=0
RptD_Y=100
RptLab=1
LabSize=60
[eeschema/libraries]
LibName1=power … LibName30=valves
LibName31=346_8
[general]
version=1
```

Что читает EESchema (`eeschema_config.cpp:263-390`, `common/projet_config.cpp`):

- Группа `/eeschema` — параметры из `GetProjectFileParameters`: `LibDir`, `NetFmt` (1 = Pcbnew, `netlist_control.h:80-90`), `HPGLSpd/Dm/Num`, `offX_*`/`offY_*` (смещения печати для A4…E), `RptD_X`, `RptD_Y`, `RptLab`, `LabSize`.
- Группа `/eeschema/libraries`: `LibName1`, `LibName2`, … **подряд**; перечисление останавливается на первом отсутствующем (`projet_config.cpp:758-781`). Имена без `.lib`, пути в Unix-нотации. Пустой список ⇒ принудительно грузится `power`.
- **`version` в `[eeschema]` обязателен и > 0** — иначе `ReCreatePrjConfig` (`projet_config.cpp:84-96`) отбрасывает файл целиком и берёт шаблон `kicad.pro`.
- При записи KiCad кладёт в корень `update=<дата>` и `last_client=<приложение>`, стирает и переписывает свою группу.
- Секции `[pcbnew]`, `[cvpcb]`, `[general]` EESchema не читает; в файле пользователя набор ключей `[pcbnew]` старее, чем в bzr2986 — генератор копирует его как есть.

Поиск библиотек (`eelibs_read_libraryfiles.cpp:48-92`, `edaappl.cpp:540-626, 1138-1193`): имя как есть относительно текущего каталога (= каталог схемы), затем каталог проекта, `LibDir`, `<kicad>/library`, `library/doc`, `template`, пользовательские `LibraryPath<n>`.

Кеш (`files-io.cpp:232-288`, `libarch.cpp`): `<имя_схемы>-cache.lib` (старое имя `<имя>.cache.lib`) — копия всех использованных компонентов; грузится первой, сортируется последней (реальные библиотеки имеют приоритет). Пересоздаётся при сохранении проекта.

Минимальный набор для открытия проекта: `.sch` + `.pro` (с `version=1`) + хотя бы одна `.lib`; `-cache.lib` желателен; `.dcm` опционален.

## 5. Схема `.sch`

### 5.1 Скелет (`sch_screen.cpp:499-549`)

```
EESchema Schematic File Version 2  date <дата>     ← байты 9..30 обязаны быть "Schematic File Version"
LIBS:<lib1>                                          ← обязательна хотя бы одна строка LIBS:; содержимое игнорируется
LIBS:<lib2>
EELAYER 25  0                                        ← "%2d %2d"; значения прощаются
EELAYER END                                          ← ОБЯЗАТЕЛЬНА: без неё файл «загружается» пустым
$Descr A4 11700 8267                                 ← имя листа + размер (размер учитывается только для User)
encoding utf-8                                       ← игнорируется
Sheet 1 1
Title ""
Date ""
Rev ""
Comp ""
Comment1 "" … Comment4 ""
$EndDescr                                            ← без неё всё дальше теряется
<элементы>
$EndSCHEMATC                                         ← фактически необязательна
```

Размеры листов (милы, `common/common.cpp:26-42`): A4 11700×8267, A3 16535×11700, A2 23400×16535, A1 33070×23400, A0 46800×33070, A 11000×8500, B 17000×11000, C 22000×17000, D 34000×22000, E 44000×34000, User 17000×11000 (или из файла). Поля листа 400 мил (`common.cpp:212-220`).

Диспетчер элементов (`load_one_schematic_file.cpp:126-188`) по **первому символу**: `$C` компонент, `$S` лист, `$D` описание; `L` компонент (старый формат), `W` провод/шина, `E` ввод в шину, `P` полилиния, `C` junction, `K` маркер (игнорируется), `N` NoConnect, `T` текст/метки; иное — «undefined object», загрузка прервана. **Пустая строка на верхнем уровне — фатальна.** Ошибка любого элемента прерывает загрузку (что успело загрузиться — остаётся).

### 5.2 Компонент `$Comp` (`sch_component.cpp:872-1010` запись, `:1013-1320` чтение)

```
$Comp
L <lib_name> <reference>                 ← пробелы → ~; пустое имя lib → _NONAME_
U <unit> <convert> <timestamp 8 hex>
P <x> <y>
[AR Path="/<sheetTS>/<cmpTS>" Ref="<ref>"  Part="<unit>" ]   ← только для сложных иерархий (>1 пути)
F 0 "<Ref>" H <x> <y> <size> 0000 C CNN  ← "F %d %s %c %-3d %-3d %-3d %4.4X %c %c%c%c" [+ " \"имя\"" для id ≥ 4]
F 1 "<Value>" H <x> <y> <size> 0000 C CNN
[F 2 …] [F 3 …] [F 4 … "имя"]
	<unit> <x> <y>                         ← "\t%-4d %-4d %-4d"; дублирует U/P и главнее
	<x1> <y1> <x2> <y2>                    ← матрица ориентации
$EndComp                                 ← проверяется по "$End" (4 символа)
```

- Позиции полей **абсолютные** (координаты листа). Флаги `%4.4X`: `0000` видимо, `0001` невидимо. Ссылка, начинающаяся с `#`, при загрузке делается невидимой. Пустые обязательные поля не пишутся; пользовательские пишутся все и перенумеровываются с 4.
- Поле в `.sch` читается `sscanf("%s %d %d %d %X %s %s")`: минимум 4 значения; выравнивание/italic/bold применяются только при 7; размер 0 → 60.
- До аннотации ссылка `DD?`; префикс = ссылка без хвостовых цифр/`?`; пустой префикс → `U`. Буква секции (`A`, `B`, …) **не хранится** — добавляется только при отрисовке (`class_libentry.cpp:261-270`).
- Timestamp — `time(NULL)` c монотонным сдвигом, 8 hex. Для листа 0 отвергается.

Матрица ориентации (`sch_component.cpp:667-792`, `transform.cpp:28-32`): точка библиотеки `(px, py)` попадает на лист в `(X + x1·px + y1·py, Y + x2·px + y2·py)`. Базовая матрица `(1,0,0,−1)` (переворот Y), далее умножение на элементарные:

| Ориентация | `x1 y1 x2 y2` |
|---|---|
| 0° | `1 0 0 -1` |
| 90° (CCW) | `0 1 1 0` |
| 180° | `-1 0 0 1` |
| 270° | `0 -1 -1 0` |
| зеркало X | `1 0 0 1` |
| зеркало Y | `-1 0 0 -1` |
| 90° + зеркало X | `0 1 -1 0` |
| 90° + зеркало Y | `0 -1 1 0` |

Всего 8 различных матриц; `GetOrientation` возвращает первое совпадение (поэтому 180°+MY читается как 0°+MX). В `kicadgen.sch.Orientation` матрицы вычисляются репликой `SetOrientation`, а не хардкодятся.

### 5.3 Прочие элементы

| Элемент | Строки | Код |
|---|---|---|
| Провод / шина / графическая линия | `Wire Wire Line` / `Wire Bus Line` / `Wire Notes Line` + `\t%-4d %-4d %-4d %-4d` (x1 y1 x2 y2). Слой — по первой букве 2-го токена | `sch_line.cpp:117-180` |
| Ввод в шину | `Entry Wire Line` / `Entry Bus Bus` + строка с **абсолютным** концом (в памяти хранится дельта) | `sch_bus_entry.cpp:58-119` |
| Соединение | `Connection ~ %-4d %-4d` (токен `~` обязателен, любой непустой) | `sch_junction.cpp:57-89` |
| Не подключено | `NoConn ~ %-4d %-4d` | `sch_no_connect.cpp:58-84` |
| Полилиния | `Poly Line <Wire|Bus|Notes> <n>` + n строк `\tx y` (порядок токенов обратный `Wire`!) | `sch_polyline.cpp:57-131` |
| Текст | `Text Notes x y orient size <~|Italic> <thickness>` + строка текста (`\n` = перевод строки) | `sch_text.cpp:407-510` |
| Локальная метка | `Text Label x y orient size <~|Italic> <thickness>` + текст | `sch_text.cpp:726-790` |
| Глобальная метка | `Text GLabel x y orient size <Input|Output|BiDi|3State|UnSpc> <~|Italic> <thickness>` + текст | `sch_text.cpp:900-990` |
| Иерархическая метка | `Text HLabel …` (как GLabel) | `sch_text.cpp:1333-1420` |
| Лист | `$Sheet` / `S x y w h` / `U <8hex>` / `F0 "имя" size` / `F1 "файл.sch" size` / `F<n≥2> "вывод" <I|O|B|T|U> <L|R|T|B> x y size` / `$EndSheet` | `sch_sheet.cpp:120-292`, `sch_sheet_pin.cpp:233-377` |

- `orient` текста/метки: 0 горизонтально вправо, 1 вертикально вверх, 2 горизонтально влево (выравнивание справа), 3 вертикально вниз. Точка `(x, y)` — якорь метки; для связности он должен лежать на проводе (на конце или внутри отрезка).
- Строка текста **не может быть пустой** (`strtok` → `NULL` → фатально). Минимум 4 значения в заголовке.
- `thickness` при чтении используется только как признак bold; KiCad пишет `GetPenSizeForBold(size)` = `size/5`.
- Выводы листа: парсер на `strtok` требует **ровно один пробел** после `F<n>` и после буквы стороны; выводы с пустым именем не пишутся; нумерация с 2.
- Маркеры ERC (`K…`) никогда не пишутся; `K` до первого загруженного элемента прерывает загрузку (устаревший флаг `itemLoaded`).

## 6. Связность и ERC

Из `eeschema/netlist.cpp` (`PointToPointConnect :950-1038`, `SegmentToPointConnect :1048-1091`, `LabelConnect :1097-1142`):

- Провода соединяются **только концами** при точном равенстве координат. Выводы, метки, junction, NoConnect — точки с `start == end`, тоже сравниваются на равенство.
- С **серединой** провода соединяются только `Connection` (junction) и метки (Label/GLabel/HLabel). Вывод, упирающийся в середину провода, **не** подключён. Три и более концов проводов в одной точке связаны и без junction; редактор ставит junction автоматически только когда конец провода или вывод попадает внутрь другого провода (`sch_screen.cpp:364-379`), при загрузке ничего не добавляется.
- Метки: `Label` — в пределах листа, `GLabel` — глобально, `HLabel` — с выводом листа в родителе, невидимый `W`-вывод — как глобальная метка с именем вывода. Имена сравниваются без регистра. Приоритет имени цепи: Label < HLabel < PinLabel < GLabel.
- Шины: чисто графические; `NAME[a..b]` разворачивается в `NAMEa…NAMEb`; вводы в шину (`Entry`) netlist пропускает.
- Листы электрически изолированы, кроме меток.

ERC (`erc.cpp:110-152`) — матрица конфликтов по умолчанию (`OK`/`WAR`/`ERR`):

## 7. Что роняет загрузку

**`.lib` целиком**: файл пуст; заголовок не `EESCHEMA-LIB…`/`Version`/`x.y`; `$HEADER` без `$ENDHEADER`.

**Один компонент `.lib`** (пропускается с warning): неверный `DEF`; строка `Ti`; поле без кавычек / с 6 токенами / с плохими `H|V`, `V|I`, `L|C|R`, `T|C|B`; неизвестная буква в `DRAW` (в т.ч. `F`); нехватка токенов у примитива; неизвестный тип или атрибут вывода; EOF внутри `DRAW` или `$FPLIST`.

**`.sch` целиком**: байты 9..30 первой строки; вторая строка не `LIBS:`.
**`.sch` с этого места** (уже загруженное остаётся): пустая строка; неизвестный первый символ; ошибка элемента (`L` не 2 токена, поле без `"`, хвост `$Comp` не 3/4 числа, нет `$End…`; `Wire`/`Entry`/`Poly` без координат; `Connection`/`NoConn` не 3 значения; текст с < 4 значений или пустой строкой; лист без `S`/`$End`, вывод листа с лишними пробелами); `K` до первого элемента.
**`.sch` молча**: нет `EELAYER END` (пустая схема), нет `$EndDescr` (потеря хвоста), неизвестный лист → `User`, строки `$Descr` > 255 байт обрезаются.

**`.pro`**: нет `version>0` в `[eeschema]` → файл игнорируется; пропуск в `LibName<n>` → хвост списка не читается.
