# Соглашения проектирования символов и схем для KiCad 2011

Правила, которых придерживается генератор (и которых стоит придерживаться при
ручной правке), с обоснованием из кода. Ссылки — на `bzr2986`.

## Сетка и единицы

- Все координаты в милах. Точки подключения выводов, концы проводов, якоря
  меток и позиция компонента `P` — **на сетке 50 мил** (лучше 100). Связность
  считается по точному равенству целых координат (`netlist.cpp:950-1038`);
  расхождение в 1 мил = разрыв цепи. Редактор библиотек ругается на выводы вне
  сетки 25 мил (`pinedit.cpp:568-691`).
- Методички дают размеры в мм. Перевод: `мил = мм × 1000 / 25.4`, затем
  округление к сетке: 5 мм → 197 → **200**, 2.5 мм → 98 → 100, 10 мм → 394 →
  400, 20 мм → 787 → 800, 25 мм → 984 → 1000, 7.5 мм → 295 → 300. Размеры
  текста к сетке не округляются (2 мм → 79 мил, как в файле студента).
- Библиотека: якорь символа `(0,0)`, Y вверх. Схема: левый верхний угол листа
  `(0,0)`, Y вниз; A4 = 11700 × 8267 мил, поля 400 мил.

## Выводы

- `(x, y)` вывода — точка подключения (свободный конец). Буква ориентации —
  направление линии к корпусу: слева от корпуса `R`, справа `L`, сверху `D`,
  снизу `U` (`lib_pin.cpp:844-894, 1466-1490`).
- Длина по умолчанию 300 мил (KiCad), в методичках 5 мм → 200. Размер имени и
  номера 50 мил по умолчанию; методичка — 2…3 мм (79…118).
- Номер вывода — не более 4 байт; имена и номера без пробелов.
- Типы: входы `I`, выходы `O`, двунаправленные `B`, пассивные `P` (резисторы,
  конденсаторы), питание микросхем `W` (Power In), выход стабилизатора `w`.
- Питание микросхемы (`Vcc`, `GND`): `unit 0` (общий для секций), тип `W`,
  атрибут `N` (невидимый). Невидимый `W`-вывод сам подключается к одноимённой
  глобальной цепи (`netlist.cpp:666-679`) — поэтому символ питания на схеме
  должен называть цепь **так же** (сравнение без регистра).
- Инверсный выход: форма `I` (кружок) плюс `~` в имени для надчёркивания
  (`~Q`).
- Отступ имени внутрь корпуса `pinNameOffset` = 40 (KiCad по умолчанию); `0` —
  имена над выводом (для резисторов/разъёмов, где имена не нужны, лучше вообще
  скрыть имена флагом `N` в `DEF`).

## Многосекционные компоненты (К555ТВ6 и т. п.)

- `unitCount` в `DEF`; секции 1..N; общие элементы (корпус, питание) — `unit 0`.
- Выводы каждой секции — со своими номерами по таблице упаковки. Одинаковые
  имена в разных секциях допустимы; одинаковые номера в одной секции —
  ошибка (генератор проверяет).
- Буква секции к ссылке (`DD1A`, `DD1B`) добавляется при отрисовке, в файле
  хранится только номер секции в `U <unit> …`.
- DeMorgan: элементы с `convert 2`; `convert 0` — общие для обоих стилей.

## Символы питания

- `DEF … P`, ссылка `#PWR`, поле Reference невидимо, Value обычно невидимо
  (методичка) — но именно текст Value виден пользователю в списке компонентов.
- Один невидимый вывод `X <NET> 1 0 0 200 D 50 50 0 1 W N`; точка подключения
  вверху, графика ниже: черта (земля, рис. 12) или галка-стрелка (питание,
  рис. 13: ножка вниз к вершине, плечи возвращаются к уровню точки
  подключения). На схеме питание ставится с поворотом 90°, раструбом к проводу
  (рис. 6).
- На схеме ссылки `#PWR01`, `#PWR02`, … (KiCad при аннотации даёт `#PWR0n`).

## Поля

- `F0` Reference над корпусом, `F1` Value под корпусом (у методички Value
  невидимо: `F1 "…" … H I …`). `F2`/`F3` пустые — не пишутся.
- В `.sch` позиции полей абсолютные: `P + T·(поле.lib)`.

## Схема

- Компонент ставится на сетку так, чтобы все его выводы легли на сетку
  (если библиотечные выводы на 100-мил сетке и `P` кратно 100 — гарантировано).
- Провода только горизонтальные/вертикальные; на каждом T-соединении — явный
  `Connection`. Конец провода на середине другого провода без `Connection` —
  не соединён.
- Локальная метка кладётся якорем **на провод**; одинаковые имена меток =
  одна цепь. Шина — графика; цепи через шину соединяются метками.
- Неиспользуемые выходы (например `~Q`) закрываются `NoConn`, иначе ERC даст
  warning «не подсоединён» (как на рис. 5 методички).
- Цепь только из входов и `W`-выводов даёт warning «not driven» — для учебной
  схемы допустимо; если нужно чисто, добавить источник (`w`, `O` или `P`).

## Файлы проекта

- `<проект>.pro` с `[eeschema] version=1`; библиотека проекта — **первой** в
  `[eeschema/libraries]`: `CMP_LIBRARY::FindLibraryComponent`
  (`class_library.cpp:957-973`) берёт первое совпадение имени в порядке
  списка, а стоковая `power.lib` содержит `GND`/`VCC` и перекрыла бы наши
  символы; `<проект>.sch`; `<проект>.lib` + `.dcm`; `<проект>-cache.lib` с
  копиями использованных компонентов; `<проект>.net` (список цепей).
- CRLF, UTF-8, дата в стиле `Ср 02.09.26 19:52:23` — как у KiCad на Windows.
- Имена компонентов — в верхнем регистре (KiCad всё равно приводит).
- Никогда не писать строку `Ti` в `.lib` (см. справочник, §2.4).
