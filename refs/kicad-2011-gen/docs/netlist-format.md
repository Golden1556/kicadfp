## 1. Последовательность действий EESchema

Кнопка «Список цепей» → `NETLIST_DIALOG::GenNetlist` (`netlist_control.cpp:464-530`):
имя файла = имя корневой схемы с расширением `net` (`:493`, `common/common.cpp:58`),
затем `SCH_EDIT_FRAME::CreateNetlist` (`netlist_control.cpp:544-580`):

| Шаг | Код | Что делает | В `kicadgen` |
|---|---|---|---|
| 1 | `sheets.AnnotatePowerSymbols()` `:549`, `sch_sheet_path.cpp:224-258` | переобозначает символы питания `#PWR01`, `#PWR02`, … (`"#" + префикс + "0" + n`, **без** дополнения нулями: десятый — `#PWR010`) | не нужно: `#`-компоненты в файл не попадают |
| 2 | `CheckAnnotate` `:552-565` | ссылки с `?` или без цифры на конце → диалог «обозначить?» | `check_annotation()` → `NetlistError` |
| 3 | `TestDuplicateSheetNames` `:567` | одинаковые имена листов → вопрос «продолжить?» | — |
| 4 | `SCH_SCREENS::SchematicCleanUp` `:575`, `sch_screen.cpp:450-496,1319-1328` | склейка коллинеарных проводов (§3.1) | `schematic_cleanup()` |
| 5 | `BuildNetListBase` `:577`, `netlist.cpp:86-310` | связность (§3) | `build_net_objects()` |
| 6 | `WriteNetListFile(NET_TYPE_PCBNEW)` `:578`, `netform.cpp:371-447` → `WriteNetListPCBNEW(f, true)` `:1486-1629` | текст файла (§2, §5) | `write_netlist_pcbnew()` |

Файл открывается `wxFopen(..., "wt")` — на Windows это CRLF (`netform.cpp:380`).

Порядок элементов схемы = порядок в `.sch`: загрузчик строит список в обратном
порядке и переворачивает его обратно (`load_one_schematic_file.cpp:212-222`).
Выводы компонента идут в порядке отсортированного списка примитивов библиотеки
(`drawings.sort()` при загрузке, `class_libentry.cpp:805`; `LIB_ITEM::operator<`,
воспроизведён `model.item_sort_key`): сначала `convert`, потом `unit` (общие
выводы `unit 0` — первыми), потом номер вывода как 4 байта `long`.

## 2. Формат файла

`EXPORT_HELP::WriteNetListPCBNEW` (`netform.cpp:1486-1629`). Все `fprintf`
дословно:

```
# EESchema Netlist Version 1.1 created  Ср 02.09.26 19:52:23     ← "# %s created  %s\n(\n" (:1499); ДВА пробела после created
(
 ( /6A9862BD $noname  X1 CONNECT {Lib=CONNECT}                  ← " ( %s %s" путь корпус, "  %s" ссылка, " %s" значение, " {Lib=%s}" (:1545-1560)
  (    1 GND )                                                  ← "  ( %4.4s %s )\n" (:1576): номер вывода в поле 4 символа, выравнивание вправо
  (    2 /1 )                                                   ← локальная метка: "<PathHumanReadable><метка>" = "/1"
  (    3 N-000001 )                                             ← без метки: "N-%.6d" от номера цепи (:1570)
  (    6 ? )                                                    ← вывод, у которого в цепи нет второго вывода
 )                                                              ← " )\n"
 …
)                                                               ← ")\n*\n" (:1584)
*
{ Allowed footprints by component:                              ← только если хоть у одного компонента есть $FPLIST (:1588-1613)
$component DD1
 DIP14*
$endlist
$endfootprintlist
}
{ Pin List by Nets                                              ← (:1617-1626)
Net 1 "" ""                                                     ← 'Net %d "<путь+метка или пусто>" "<метка или пусто>"' (:1795-1810)
 X1 3                                                           ← " %s %.4s\n" ссылка и номер вывода (:1835,1850)
 DD1 13
Net 3 "GND" "GND"                                               ← глобальные (PINLABEL/GLABEL) без префикса пути
Net 10 "/1" "1"                                                 ← локальная метка: "/" + метка
}
#End
```

Детали:

- **Путь компонента** `/<timestamp>` = `SCH_SHEET_PATH::Path()` (`sch_sheet_path.cpp:171-187`:
  `/` + `%8.8lX/` на каждый *вложенный* лист, корень не входит) + `%8.8lX` метки
  времени компонента (`sch_component.cpp:329-335`). Для плоской схемы —
  `/6A9862BD`. Hex в верхнем регистре.
- **Корпус**: поле F2; пусто или `~` (`sch_field.h:71-76`) → `$noname`, иначе
  текст с заменой пробелов на `_` (`:1536-1541`).
- **Ссылка**: `SCH_COMPONENT::GetRef` (`sch_component.cpp:338-370`): запись
  `AR Path=…` для данного пути, иначе поле F0. Символы, чья ссылка начинается с
  `#` (питание), **в файл не попадают** (`netform.cpp:568-571`).
- **Значение**: текст F1 с заменой пробелов на `_`; **`{Lib=…}`** — имя
  библиотечного компонента из строки `L` (`:1557-1560`).
- **Порядок компонентов** — порядок в `.sch` (по листам, внутри листа — по
  списку отрисовки). Многосекционный компонент пишется **один раз** при первой
  встрече ссылки; его выводы собираются по всем секциям (§5).
- **Порядок выводов** внутри блока — `RefDesStringCompare`
  (`common/string.cpp:414-466`): `<буквы><число><хвост>`, буквы без регистра,
  число по значению: `1, 2, 10, A1, a2, A10`.
- **Имя цепи в строке вывода** — `sprintPinNetName` (`netform.cpp:463-500`),
  §4. Пробелы → `_` (`:1574`). Пусто → `?` (`:1571-1572`).
- Секция **`{ Pin List by Nets`** — `writeGENERICListOfNets` (`:1768-1855`):
  по цепям в порядке номеров; печатаются только цепи, где **не меньше двух**
  выводов обычных компонентов (первый вывод откладывается до появления второго,
  `:1826-1851`); выводы символов питания и дубликаты (`m_Flag`, §5) пропускаются.
  Цепь 0 (шины) выводов не содержит и не печатается.
- Дата — `DateAndTime()` (`common/string.cpp:175-201`): `wxDateTime::Format("%c")`,
  в русской Windows `Ср 02.09.26 19:52:23` (как в `.lib`/`.sch`; `textio.kicad_date`).

Вариант ORCADPCB2 (`with_pcbnew=false`): заголовок `( { … created  … }`, без
`{Lib=…}`, без секций после `*`.

## 3. Алгоритм связности (BuildNetListBase)

`netlist.cpp:86-310`. Единица работы — `NETLIST_OBJECT`
(`class_netlist_object.h:61-130`): тип, лист (`m_SheetList`), точка/отрезок
(`m_Start`, `m_End`), метка (`m_Label`), код цепи (`m_NetCode`), код шины
(`m_BusNetCode`), номер члена шины, признак подключённости, кандидат имени.

### 3.1 Предварительная склейка проводов

`SCH_SCREEN::SchematicCleanUp` (`sch_screen.cpp:450-496`): для каждой линии
(`SCH_LINE`: провод, шина, графическая линия) перебираются последующие линии;
`SCH_LINE::MergeOverlap` (`sch_line.cpp:260-321`) при общем конце и одинаковой
ориентации (обе горизонтальные, обе вертикальные или равный `atan2`) сливает
их в первую, вторая удаляется, перебор начинается **с головы списка**. Слой
должен совпадать. Побочные эффекты воспроизведены дословно, включая
перестановку концов при общем начале и известную странность: частично
перекрывающий дубликат с общим началом **укорачивает** линию
(`kicadgen.netlist.schematic_cleanup`, тест `test_schematic_cleanup_partial_overlap_quirk`).

Следствие для рисования: два коллинеарных провода, стыкующихся на выводе,
после склейки становятся одним проводом, и вывод оказывается в его середине
→ **не подключён**. Нужен `Connection` (редактор ставит его сам при
рисовании, генератор — тоже, см. `docs/conventions.md`).

### 3.2 Создание объектов (`AddConnectedObjects`, `netlist.cpp:506-735`)

Обход листов — `SCH_SHEET_LIST` (`sch_sheet_path.cpp:513-549`): корень, затем
подлисты в порядке отрисовки, в глубину. На каждом листе, в порядке списка:

| Элемент `.sch` | Объект | Координаты | Примечание |
|---|---|---|---|
| `Wire Wire Line` | `NET_SEGMENT` | оба конца | `Wire Notes Line` пропускается |
| `Wire Bus Line` | `NET_BUS` | оба конца | у шин только `m_BusNetCode` |
| `Connection` | `NET_JONCTION` | точка | |
| `NoConn` | `NET_NOCONNECT` | точка | |
| `Text Label` | `NET_LABEL` | якорь | |
| `Text GLabel` | `NET_GLOBLABEL` | якорь | |
| `Text HLabel` | `NET_HIERLABEL` | якорь | |
| метка вида `NAME[a..b]` | `NET_*BUSLABELMEMBER` × (b−a+1) | якорь | `IsBusLabel` `:785-846`, `ConvertBusToMembers` `:852-895`: имена `NAMEa`…`NAMEb`, `m_Member` = номер; нечисловые границы читаются как `strtol` (0) |
| вывод компонента | `NET_PIN` | `P + T·(x,y)` вывода | фильтр по секции `GetUnitSelection` (`sch_component.cpp:447-470`) и `convert`; `m_Link` = компонент, `m_PinNum` = номер |
| невидимый вывод типа `W` (Power In) | + `NET_PINLABEL` | та же точка | `:666-680` — «глобальная метка» с именем вывода. Видимый `W` такой метки **не** создаёт |
| вывод листа (`F<n>` в `$Sheet`) | `NET_SHEETLABEL` | точка | `m_SheetListInclude` = путь + этот лист |
| `Entry`, `Text Notes`, `Poly` | — | | вводы в шину чисто графические |

Компонент, которого нет в библиотеках, выводов не даёт (`:634-635`).

### 3.3 Проходы

1. **Сортировка по листу** (`:116-118`, `SortItemsBySheet` `:1158-1164`:
   глубина, затем метки времени). `std::sort` — нестабильная; см. §6.
2. **Локальная связность** (`:120-222`), объекты по порядку, `LastNetCode`
   начинается с 1; `istart` — первый объект текущего листа:
   - `PIN`, `PINLABEL`, `SHEETLABEL`, `NOCONNECT`: если код уже есть —
     пропуск; иначе как `SEGMENT`;
   - `SEGMENT`: код (если 0 — новый), `PointToPointConnect` (`:950-1038`):
     все объекты **того же листа** типов `SEGMENT/PIN/LABEL/HIERLABEL/GLOBLABEL/
     SHEETLABEL/PINLABEL/JONCTION/NOCONNECT`, у которых **любой конец совпадает**
     с любым концом опорного объекта, получают его код; если у них уже есть
     код — `PropageNetCode` (`:901-930`) переписывает **весь** старый код на
     код опорного объекта;
   - `JONCTION`: код + `SegmentToPointConnect` (`:1048-1091`) — все `SEGMENT`,
     на которых лежит точка (`SegmentIntersect`, `dangling_ends.cpp:19-33`,
     концы включительно), сливаются; затем то же для шин через `m_BusNetCode`;
   - `LABEL/HIERLABEL/GLOBLABEL`: код + `SegmentToPointConnect` — метка
     соединяется с проводами, на которых лежит её якорь (в середине тоже);
     с выводом напрямую метка соединяется только через `PointToPointConnect`
     самого вывода (совпадение точек);
   - `BUS`: `m_BusNetCode` + `PointToPointConnect(ISBUS)`;
   - `*BUSLABELMEMBER`: `m_BusNetCode` + `SegmentToPointConnect(ISBUS)`
     (условие `GetNet()==0` вместо `m_BusNetCode==0` — как в коде, `:202-212`).
3. **Члены шинных меток** `ConnectBusLabels` (`:740-780`): члены с одинаковыми
   `m_BusNetCode` и `m_Member` получают одну цепь.
4. **Метки** (`:231-268`, `LabelConnect` `:1097-1142`) для `LABEL`, `GLOBLABEL`,
   `PINLABEL`, `BUSLABELMEMBER`, `GLOBBUSLABELMEMBER` в порядке списка:
   объекты-метки с тем же текстом (`CmpNoCase`, **без учёта регистра**)
   получают код опорной метки. Через границу листа проходят только
   `PINLABEL`, `GLOBLABEL`, `GLOBBUSLABELMEMBER`, причём глобальная метка
   соединяет только глобальные того же типа; `HIERLABEL` через листы не
   соединяется (только через `SHEETLABEL`).
5. **Иерархия** (`:270-278`, `SheetLabelConnect` `:463-500`): вывод листа ↔
   `HIERLABEL` с тем же именем внутри этого листа.
6. **Сортировка по коду** (`:280-281`, нестабильная) и **сжатие** (`:291-300`):
   коды перенумеровываются 1, 2, … в порядке возрастания; объекты с кодом 0
   (шины) остаются 0.
7. `SetUnconnectedFlag` (`:1168-1251`) и `FindBestNetNameForEachNet` (`:322-368`) — §4.

Итог: цепи нумеруются по **окончательному** коду, а он равен коду того
объекта, который последним «перетянул» цепь на себя (`PropageNetCode` всегда
переписывает код найденного объекта на код текущего). Поэтому цепи с метками
(метки идут в `.sch` после проводов) получают большие номера, чем цепи без
меток, а не по порядку выводов. Так в `346_8` цепь X1.3–DD1.13 стала `N-000001`,
а цепи меток `1`, `2`, `3` — 10, 11, 12.

## 4. Имя цепи и признак подключённости

**`m_FlagOfConnection`** (`SetUnconnectedFlag`, `netlist.cpp:1168-1251`), по
цепи: `PAD_CONNECT`, если в цепи **два и более `NET_PIN`** (выводы символов
питания тоже считаются); иначе `NOCONNECT_SYMBOL_PRESENT`, если есть `NoConn`;
иначе `UNCONNECTED`. Одиночный вывод с меткой, но без второго вывода —
`UNCONNECTED`, и в файле у него `?`.

**Кандидат имени** (`FindBestNetName`, `:380-458`) — среди меток цепи
(`LABEL`, `HIERLABEL`, `PINLABEL`, `GLOBLABEL`) по приоритету
`LABEL < HIERLABEL < PINLABEL < GLOBLABEL`; при равном приоритете: для
глобальных — по `wxString::Cmp` (по кодам символов: `NET_A` < `net_a`), для
локальных — сначала более короткий путь листа, потом `Cmp`.

**Текст имени** (`sprintPinNetName`, `netform.cpp:463-500`):

| Ситуация | В строке вывода | В `Net %d "…" "…"` |
|---|---|---|
| код 0 или не `PAD_CONNECT` | пусто → `?` | (цепь не печатается) |
| кандидат `PINLABEL`/`GLOBLABEL` | `<метка>` (`GND`, `Vcc`) | `"GND" "GND"` |
| кандидат `LABEL`/`HIERLABEL` | `<PathHumanReadable><метка>` (`/1`; если путь длиннее 32 символов — `Path()` c метками времени) | `"/1" "1"` |
| меток нет | `N-%.6d` от номера цепи | `"" ""` |

`PathHumanReadable` (`sch_sheet_path.cpp:190-204`) = `/` + `<имя листа>/`… для
вложенных листов; для корня — `/`.

## 5. Список компонентов и их выводов

`findNextComponentAndCreatePinList` (`netform.cpp:550-636`):

1. Компонент со ссылкой на `#` или без библиотечного описания — пропуск.
2. Одна секция: `LIB_COMPONENT::GetPins(unit, convert)` (`class_libentry.cpp:489-512`),
   каждому выводу ищется его `NET_PIN` (`addPinToComponentPinList` `:1632-1665`:
   тот же компонент, тот же номер, тот же лист; берётся первый найденный).
3. Несколько секций (`GetPartCount() > 1`): ссылка запоминается
   (`m_ReferencesAlreadyFound`, с учётом регистра); `findAllInstancesOfComponent`
   (`:1726-1765`) обходит **все листы** и **все** компоненты с той же ссылкой
   (`CmpNoCase`) и добавляет выводы каждой секции (`unit`/`convert` фильтр).
   Общие выводы (`unit 0`, питание) попадают по разу на секцию.
4. Сортировка `sortPinsByNum` (`:450-454`, `RefDesStringCompare`).
5. `eraseDuplicatePins` (`:1672-1720`): среди подряд идущих выводов с одним
   номером остаётся подключённый (`PAD_CONNECT`), иначе первый; у удалённых
   `m_Flag = 1`, и в `{ Pin List by Nets` они не печатаются.

Так у `DD1` (К555ТВ6, 2 секции) выводы 7 и 14 встречаются дважды, печатаются
по разу; блок `DD1` содержит 14 строк в порядке 1…14.

## 6. Что не гарантируется байт в байт

- **Нумерация безымянных цепей и порядок выводов внутри `Net %d`.** Обе
  сортировки в `BuildNetListBase` — `std::sort` (нестабильная). Для одного
  листа все ключи первой сортировки равны, для второй равны внутри цепи;
  libstdc++ при `n > 16` переставляет равные элементы (introsort), MSVC — иначе.
  `kicadgen` использует стабильную сортировку (порядок `.sch`). Связность,
  имена меток/глобальных цепей и содержимое блоков компонентов от этого не
  зависят; может отличаться только соответствие `N-00000x` ↔ цепь и порядок
  строк внутри `Net %d`. Эталонного `.net` от GUI для `346_8` нет, сверить не с
  чем.
- Дата — текущая локаль пользователя.
- `AnnotatePowerSymbols` меняет ссылки `#PWR…` в памяти (и в `.sch` после
  сохранения), на `.net` не влияет.
- Шинные метки с нечисловыми границами (`A[x..y]`) в C++ — неинициализированная
  переменная; здесь — `strtol` → 0.

## 7. Использование

```bash
python3 -m kicadgen.netlist examples/346_8/346_8.sch examples/346_8/My_lib.lib \
        --date "Ср 02.09.26 19:52:23" --print-nets       # -> examples/346_8/346_8.net (CRLF)
python3 -m unittest tests.test_netlist -v
```

```python
from kicadgen.sch import load_schematic
from kicadgen.reader_lib import load_library
from kicadgen import netlist as N

sch, _ = load_schematic('346_8.sch')
lib, _ = load_library('My_lib.lib')          # или список библиотек: [lib, cache]
nets = N.build_nets(sch, lib)                # [Net(code, name, label, pins=[(ref, num)], connected)]
text = N.write_netlist_pcbnew(sch, lib, date='Ср 02.09.26 19:52:23')
N.save_netlist(text, '346_8.net')            # CRLF
```

Иерархия: `write_netlist_pcbnew(..., loader=N.file_sheet_loader(dir))` грузит
подлисты по имени файла из `$Sheet`.

Цепи `346_8` (ТЗ §3.3): `GND` = X1.1, DD1.7, R1.1 (+ `#PWR01`, `#PWR02`);
`Vcc` = X1.8, DD1.14 (+ `#PWR03`); `/1` = X1.2, DD1.1; `/2` = X1.4, DD1.8;
